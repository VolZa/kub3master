ADR-002. Структура проєктної документації
Принцип

ERP не повинна вигадувати власну класифікацію виробів, а повинна повторювати структуру проєктної документації.

Базова ієрархія:

Проєкт
    │
    ├── Документ (Альбом)
    │       │
    │       ├── Вироби
    │       │      │
    │       │      ├── Деталі
    │       │      └── BOM
    │       │
    │       └── Специфікації
    │
    └── Будинки
            │
            ├── Placement
            ├── Виробництво
            └── Монтаж
Сутність Project

Наприклад

Поле	Значення
Code	Д-05/2020
Name	Реконструкція ...
Сутність ProjectDocument

(замість просто "Album")

Поле	Значення
ProjectId	1
Code	КР.9
FullCode	Д-05/2020 - КР.9
Name	Плити перекриття. Арматурні вироби
Discipline	КР
Область унікальності кодів

Коди виробів і деталей не є глобальними.

Вони унікальні в межах документа проєкту.

Тобто:

Д-05/2020 - КР.3 - ГС-2

≠

Д-05/2020 - КР.9 - ГС-2
Будинок

Будинок є екземпляром реалізації проєкту.

Наприклад

Проєкт Д-05/2020
        │
        ├── H001
        ├── H002
        └── H003

Усі вони використовують один і той самий комплект документації.

Дуже важливе правило

Після сьогоднішнього обговорення я б розділив ERP на дві незалежні області.

1. Проєктна область (майже незмінна)
Project

↓

ProjectDocument

↓

Catalog

↓

BOM

Вона описує що потрібно виготовити.

2. Виробнича область (постійно змінюється)
House

↓

Placement

↓

Production

↓

Material Usage

↓

Shipment

Вона описує що вже виготовлено.
