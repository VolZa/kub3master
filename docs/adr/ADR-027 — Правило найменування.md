Тобто:

для головної сутності таблиці використовується просто Code;
для посилання на іншу сутність — уточнююча назва (DocumentCode, MaterialCode тощо), якщо це необхідно для уникнення неоднозначності.

ADR-027 — Правила найменування кодів сутностей
Статус

Accepted

Рішення

У ERP КУБ використовується таке правило найменування полів.

1. Для основної сутності таблиці використовується поле
   Code

Приклади:

04_Catalog
Code

00_Elements
Code

18_Projects
Code

20_Houses
Code 2. Якщо необхідно звернутися до коду іншої сутності, використовується уточнююча назва

Наприклад:

DocumentCode
MaterialCode
HouseCode
ProjectCode 3. Для зв'язків використовуються тільки ID
ProjectID

ProjectDocumentID

MaterialID

ElementID

ParentID

ChildID 4. Code не використовується як технічний ключ

Поле Code є бізнес-ідентифікатором.

Внутрішні зв'язки між таблицями виконуються тільки через ID.

Наслідки
модель стає читабельнішою;
відсутня неоднозначність між кодом елемента та кодом документа;
усі модулі ERP використовують єдину систему найменування;
спрощується написання TypeScript-моделей, репозиторіїв і маперів.

Я б ще запропонував невелике правило щодо назв
