ADR-028 — Project Context
Статус

✅ Прийнято

Контекст

ERP КУБ підтримує багатопроєктну модель.

Один будинок будується за одним проєктом.

Один проєкт складається з багатьох документів (альбомів).

Один виріб може містити складові, що належать різним документам одного проєкту.

Приклад:

Проєкт Д-05/2020

КР.6
└── Плита П-1.23

КР.9
└── Закладна МК-17

При формуванні BOM або технологічного звіту використовуються елементи з кількох документів одночасно.

Рішення

У ERP існує єдиний робочий контекст — ProjectContext.

Він описує поточний будинок, поточний проєкт та всі документи цього проєкту.

export interface ProjectContext {
readonly house: Readonly<House>;

readonly project: Readonly<Project>;

readonly projectDocuments: ReadonlyMap<
string,
Readonly<ProjectDocument>

> ;
> }

де ключем ReadonlyMap є ProjectDocumentID.

Формування контексту

ProjectContextService виконує такі кроки:

House
│
▼
Project
│
▼
Усі ProjectDocuments цього Project
│
▼
ProjectContext

Контекст формується один раз після вибору будинку.

Правила використання

Після створення ProjectContext бізнес-сервіси не повинні повторно звертатися до:

HouseRepository
ProjectRepository
ProjectDocumentRepository

для отримання інформації про поточний будинок, проєкт або документи.

Уся ця інформація отримується через ProjectContext.

Визначення документа елемента

Кожен елемент ERP містить поле:

ProjectDocumentID

Документ елемента визначається виключно цим полем.

Отримання документа виконується через:

context.projectDocuments.get(element.projectDocumentID)

Наслідки
Переваги

- один контекст для всієї ERP;
- відсутність дублювання звернень до репозиторіїв;
- підтримка виробів, що складаються з елементів різних документів;
- спрощення бізнес-сервісів;
- швидкий доступ до інформації про документ через ReadonlyMap.
  Обмеження

Один ProjectContext може містити лише документи одного проєкту.

Для переходу на інший проєкт формується новий ProjectContext.

Коментар

Це рішення повністю відповідає реальній роботі технолога. Він не відкриває окремий альбом перед кожною операцією — він працює з будинком, а система сама знає, що для цього будинку використовується проєкт Д-05/2020 і всі його альбоми. Якщо плита бере закладну з КР.9, а арматурний каркас із КР.6, ERP знаходить потрібний документ за ProjectDocumentID елемента. Технологу не потрібно перемикати контексти або думати, з якого альбому походить деталь — це стає відповідальністю системи.

На мою думку, це одне з найсильніших архітектурних рішень у проєкті ERP КУБ, оскільки воно природно відображає структуру проєктної документації та добре масштабуватиметься на всі наступні модулі: BOM, планування, облік матеріалів, виробництво і звітність.
