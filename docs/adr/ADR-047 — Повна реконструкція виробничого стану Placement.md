ADR-047 — Повна реконструкція виробничого стану Placement

Status: Accepted

Context

Під час розробки та тестування системи дані 01_Виготовлення та 13_Placement можуть тимчасово розходитись.

Зокрема, тестові записи в 01_Виготовлення можуть бути створені, змінені або видалені, тоді як у 13_Placement та ManufacturingSyncState можуть залишатися результати попередньої синхронізації.

Для відновлення узгодженого стану потрібна окрема адміністративна операція повної реконструкції.

Decision

Ввести операцію повної реконструкції виробничого стану Placement — MFG-RESET-001.

Джерелом істини для реконструкції є поточний стан 01_Виготовлення.

Операція повинна повністю перебудовувати:

виробничий стан 13_Placement;
ManufacturingSyncState.

ManufacturingSyncState не використовується як джерело даних під час реконструкції.

Операція має два режими:

dryRun — аналіз майбутніх змін без запису;
execute — застосування реконструкції.

Повна реконструкція є окремою адміністративною операцією і не замінює інкрементальну синхронізацію Manufacturing → Placement.

Consequences
Позитивні
можна безпечно виконувати масові тести;
наслідки старих тестових записів можна усунути;
13*Placement та ManufacturingSyncState можна відновити з актуального 01*Виготовлення;
результат реконструкції є детермінованим;
інкрементальна синхронізація не залежить від залишків тестових даних.
Обмеження
операція є адміністративною та не повинна виконуватися автоматично в штатному виробничому циклі;
перед execute бажано виконувати dryRun;
правила зміни статусів Placement повинні бути окремо визначені в алгоритмі MFG-RESET-001.
