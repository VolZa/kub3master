## Термінологічні та редакційні примітки

Англійська термінологія залишається основною для canonical names / (канонічних назв). При першому змістовному використанні доменного, архітектурного або технічного терміна, якщо пояснення корисне для розуміння чи навчання, надається формат EnglishTerm / (Український переклад або коротке пояснення). Документація допомагає читати модель ERP КУБ і поступово засвоювати англійську технічну лексику.

Власні назви TypeScript, Google Apps Script і Google Sheets не отримують штучного перекладу. Програмні ідентифікатори, поля, прикладні ID та код залишаються без перекладу. Корисні локальні словники збережено; уніфіковано формат і відповідники, прибрано механічні визначення власних назв.

- Manufacturing / (Запис про виготовлення) розрізняється з ProductionConfirmed / (Підтвердження виготовлення).
- MaterialFlow / (Матеріальний потік) є канонічним внутрішнім представленням відповідного розрахунку Business Layer / (Бізнес-рівня), а не джерелом історичної істини Consumption.
- Event / (Подія) у DDS-001 означає саме MaterialFlowEvent / (Подія матеріального потоку), а не будь-яку domain event / (доменну подію).
- Unresolved Material Stock / (Матеріал із невстановленим документальним походженням) є агрегованим станом availability / (доступності). Provenance / (походження) Actual Consumption використовує конкретний UnresolvedReceipt / (Невизначене надходження).
- MaterialReconciliation / (Узгодження матеріалу) уточнює документальну визначеність походження матеріалу; вже створений immutable / (незмінний) MaterialFlow не змінюється.
- batch-specific weightPerMeter / (маса одного метра для конкретної партії) може використовуватися для приведення доступності Batch з маси до primary flow unit / (первинної одиниці матеріального потоку) без повторного визначення геометрії чи чистого Requirement.
- Змістові межі чистого Requirement та кількості після MaterialLossPolicy збережені й явно пояснені у визначенні та входах Actual Allocation.
- У US-01 quantity редакційно уточнене як receivedQuantity та receivedUnit; це не остаточний persistence / (збереження даних) contract / (контракт).
- Редакційна помилка пояснення MC-07 виправлена без зміни Accepted MC-07; буквальне копіювання source / (джерела) не є підставою зберігати помилку.
- Написання прикладних ID `R_12_А500С` у DOCX і `R*12*А500С` у Markdown залишаються джерельними варіантами, не новим правилом нормалізації.
- Числові приклади та обґрунтування першої хвилі збережені; вони не встановлюють нульової LossPolicy чи approval-стану / (стану затвердження) Allocation.
- Original/source ADR / (Оригінальний ADR-джерело) за межами робочого каталогу не змінювався. Робоча канонічна копія ADR-048 отримала лише погоджені редакційні зміни, термінологічні уточнення і cross-references / (перехресні посилання); нормативні рішення та інваріанти не змінені.
