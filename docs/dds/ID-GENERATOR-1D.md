# Implementation Slice 1D — ID generator

Локальні зміни відносно `e4f697c`. Міграція, Google Sheets, commit та clasp push/deploy не виконувалися.

`generateIdByType(type): string` зберігає публічний контракт. Нові діапазони: material 1000001–1999999, part 2000000–2999999, assembly 3000001–3999999, product 4000000–4999999. Діапазони не використовуються для класифікації існуючих сутностей; legacy ID не змінюються.

Кандидат обчислюється як максимум LastID, нижньої межі мінус один, історичного резерву міграції та всіх зайнятих ID відповідного діапазону, плюс один. Історичні резерви Product 4000000–4000013 і Part 2000000–2000009 залишаються зайнятими після видалення записів. LastID зберігає резервування навіть без наступної вставки сутності.

Лічильник читається з перших двох колонок `_Config_ID_Counters`, як у базовій реалізації. Відсутні або дубльовані рядки типу, некоректні LastID і вичерпання діапазону спричиняють помилку без запису. Дозволені невід'ємні безпечні цілі числа та рядки десяткових цифр із зовнішніми пробілами. Порожні, дробові, нескінченні, від'ємні та структурно некоректні значення відхиляються.

Зайняті ID читаються за єдиним заголовком `ID` з усіх рядків `00_Elements` і `05_Materials`, без фільтра Type або IsActive. Числові та рядкові значення нормалізуються чисельно, включно з початковими нулями. Порожні ID пропускаються, непорожні некоректні ID блокують резервування з повідомленням про лист і рядок.

MASTER відкривається через наявний `SpreadsheetProvider.open(SpreadsheetKey.MASTER)`. Активна таблиця не використовується генератором.

Script lock отримується до читання MASTER, timeout 30 секунд. Читання, перевірка, запис LastID і flush виконуються під одним lock; release — у finally. ID повертається лише після успішного setValue і flush. Script lock не залежить від активного документа і підходить також для web app; це перевірено за [документацією Google](https://developers.google.com/apps-script/reference/lock/lock-service). Flush перед release відповідає [рекомендації Google](https://developers.google.com/apps-script/reference/lock/lock#releaseLock()). Реальне виконання GAS не тестувалося, оскільки цей slice дозволяє лише локальні перевірки.

Перевірені точки виклику: `part.service`, `root-element.service`, `material.service`, `element.factory`. Усі використовують string ID генератора. Водночас `GoogleSheetsElementRepository.insert(row)` приймає довільний ID і сам не отримує lock. Прямі вставки, ручне редагування, імпорт або інші script projects можуть обходити резервування. Script lock серіалізує лише виклики цього Apps Script project; він не блокує зовнішніх авторів. Репозиторій Elements також досі використовує getActive через getSheetByNameSafe: запуск створення сутності з іншої активної таблиці залишається окремим архітектурним ризиком поза цим slice.

Прикріплені вимоги обриваються на пункті тестів «9. Не». Додатково покрито історичні резерви без наявних записів, повторні резервування, некоректні лічильники, дублікати, межі всіх типів, timeout та помилки lock/read/write/flush. Моки перевіряють читання та flush під отриманим lock; вони не замінюють інтеграційне тестування реального паралельного GAS виконання.
