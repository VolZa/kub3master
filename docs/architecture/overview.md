Архітектурний принцип розвитку ERP

Існуючі модулі не переписуються без необхідності. Нові можливості додаються шляхом безпечного розширення існуючої моделі із збереженням зворотної сумісності.

Для нашого випадку це означає:

Рівень 2. Repository

Repository починають враховувати ProjectDocument.

Наприклад

замість

getByCode(code)

стає

getByCode(projectDocumentId, code)

або

getByScopedCode(scope, code)

Але старий метод можна залишити як обгортку для режиму одного проєкту, щоб не зламати існуючий код.

Рівень 3. Service
